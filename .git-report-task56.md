## Task 5 — Dedup (`src/romm_hub/dedup.py`)

Created:
- `src/romm_hub/dedup.py`
- `tests/test_dedup.py`

Interfaces:
- `FileHashes` (frozen dataclass): `crc32: str`, `md5: str`, `sha1: str` — all lowercase hex.
- `hash_file(path, chunk_size=1 MiB) -> FileHashes` — single streaming pass (one `while` loop
  reading in `chunk_size` pieces) updating a running `zlib.crc32` accumulator plus
  `hashlib.md5`/`hashlib.sha1` incrementally, never reading the file whole and never walking it
  more than once.
- `find_duplicate(hashes, existing_roms) -> dict | None` — checks `sha1_hash` across all roms
  first, then `md5_hash`, then `crc_hash` (priority order), case-insensitive (`.lower()` on both
  sides). Any rom whose relevant hash field is `None`/falsy is skipped outright — a null-vs-null
  comparison can never register as a match.

## Task 6 — Job queue (`src/romm_hub/jobs.py`)

Created:
- `src/romm_hub/jobs.py`
- `tests/test_jobs.py`

Interfaces:
- `JobState(str, Enum)`: `PENDING`, `DOWNLOADING`, `UPLOADING`, `DONE`, `FAILED`,
  `SKIPPED_DUPLICATE`.
- `Job` dataclass: `id`, `plugin`, `source_id`, `title`, `platform`, `state`, `error`,
  `local_path`.
- `JobQueue(db_path)`:
  - `enqueue(plugin, source_id, title, platform) -> Job` — inserts as `PENDING`.
  - `claim_next() -> Job | None` — picks oldest `PENDING`, marks `DOWNLOADING`. Uses an
    explicit `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK` transaction (connection opened with
    `isolation_level=None` so sqlite3's implicit-transaction machinery doesn't fight the
    explicit one) so two callers against the same db file cannot both claim the same job.
  - `set_state(job_id, state, error=None, local_path=None)` — always updates `state`;
    `error`/`local_path` are only overwritten when a caller actually passes a value, so a
    `local_path` recorded when a download finishes survives later transitions (e.g. to
    `UPLOADING`/`DONE`) that don't re-pass it.
  - `get(job_id) -> Job | None`.
  - `list(state=None) -> list[Job]`.
  - `reset_stale() -> list[Job]` — moves `DOWNLOADING`/`UPLOADING` back to `PENDING`, returns
    the (now-`PENDING`) jobs that were reset.
- Schema (`CREATE TABLE IF NOT EXISTS jobs (...)`) created on first use; the constructor
  `mkdir(parents=True, exist_ok=True)`s the parent directory so a path whose directories don't
  exist yet still works.

## Concerns / notes for Task 7

- `set_state`'s "None means leave unchanged" semantics for `error`/`local_path` is a design
  choice, not explicitly specified in the plan brief — documented in the docstring and pinned by
  `test_local_path_and_error_survive_a_later_set_state_that_omits_them`. There is currently no
  way to explicitly clear `error` back to `NULL` via `set_state`; if Task 7 ever needs that (e.g.
  a retried job that succeeds should stop showing a stale error), it will need a small follow-up
  (a sentinel default, or a dedicated `clear_error` call).
- `claim_next()` transitions `PENDING -> DOWNLOADING` directly (not just "non-PENDING") since
  downloading is the first real work in the Task 7 pipeline; Task 7 is expected to call
  `set_state(job_id, JobState.UPLOADING, ...)` itself once the download completes.
